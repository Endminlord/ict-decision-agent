# ict-track2-mcp · 引用回查 MCP 服务

给智能体用的**引用回查**工具：把检索结果里的 `chunk_id` 变回可核对的原文依据，并验证一段引用是否真的出现在语料里。

用于华为 ICT 大赛中国创新赛 · 赛题 2（AgentArts 平台）——**自包含**设计，无外部服务依赖，可直接以 UVX 方式接入 AgentArts。

## 为什么自包含

AgentArts 对 MCP 服务有两条路：

| 方式 | 要求 | 我们为什么选它 / 不选它 |
|---|---|---|
| SSE / streamableHttp | 服务须在**公网可访问地址**（IP 不应为内网） | ✗ 需要买 ECS 或开隧道，引入额外故障点 |
| **UVX / NPX** | 包发布到 PyPI / npm，平台在沙箱里执行 | ✓ **本包**——数据打包进 wheel，零外部依赖 |

代价：包必须自带数据。本包把语料子集的**片段 + 定位信息**打进 wheel（11 MB），**不打包全文**——因为「可回查」的定义是「能定位到原文的哪一块、哪一偏移」，不是「把全文吐出来」。

## 三个工具

| 工具 | 输入 | 输出 |
|---|---|---|
| `lookup_chunk` | `chunk_id` | 该块原文片段、文档标题、日期、来源、字符偏移；不存在则明确返回 `found: false` |
| `verify_quote` | `quote`（≥4 字符）、`max_hits` | 前 `max_hits` 条命中位置（含 `chunk_id`、标题、偏移、匹配方式 `exact`/`normalized`）；`hit_count` 是全量命中数，`returned_hits` 是本次返回条数；**命中为空表示该引用无法核实** |
| `list_sources` | `topic`（可选）、`top` | 按来源 / 按年份 / 按文档的统计 |

`verify_quote` 是反幻觉的关键：模型生成的引用必须能被它验证，验证不通过就不该写进答案。

## 安装与使用

```bash
# 本地开发
uv venv .venv --python 3.10
uv pip install --python .venv/bin/python -e .

# 跑 MCP 服务（stdio）
.venv/bin/ict-track2-mcp

# 自测（四层，共 96 条判据）
python3 scripts/build_data.py --self-test          # 数据生成 6/6
python3 tests/test_lookup.py                       # 查询层 32/32
.venv/bin/python tests/test_mcp_protocol.py        # MCP 协议往返 26/26

# 打包
uv build          # → dist/ict_track2_mcp-0.1.0-py3-none-any.whl（11.7 MB，含数据）
```

在 AgentArts 里接入（创建 MCP → UVX 方式）时，包名填 `ict-track2-mcp`。

## 数据

数据文件 `src/ict_track2_mcp/data/chunks.jsonl.gz`（11 MB，15,000 块，1,112 万字）由脚本从语料子集生成：

```bash
python3 scripts/build_data.py                    # 默认源与输出
python3 scripts/build_data.py --limit 2000       # 只取 2000 块（快速验证）
```

源格式：JSONL，字段 `chunk_id / doc_id / char_offset / title / date / source / text`。

## 全领域通用（引擎与领域无关）

引擎不假设语料属于哪个行业——**换任何领域的语料都不用改一行代码**，只换数据文件：

```bash
ict-track2-mcp --data /path/to/other-domain.jsonl.gz      # 显式指定
ICT_TRACK2_DATA=/path/to/x.jsonl.gz ict-track2-mcp        # 环境变量
ict-track2-mcp                                            # 包内默认（政务语料）
```

`list_sources` 返回的 `stats` 也不含领域假设：`chunks` / `documents` / `sources` / `data_path` / `year_range` / `top_sources`——后两个字段用来快速判断「装的到底是哪个领域」。

**怎么验证**：`tests/test_domains.py` 用**同一套 8 条判据**跑任意语料。判据本身不含领域假设——测试数据全部从语料自身提取（第一块的正文、标题），所以对政务、医疗、法律、制造……都成立。

```bash
python3 tests/test_domains.py --all /path/to/domain-dir   # 跑目录下所有 .jsonl.gz
python3 tests/test_domains.py --data x.jsonl.gz           # 单个文件
```

10 条判据：D1 可加载 · D2 stats 字段齐全 · D3 `lookup` 命中真实 id · D4 `verify` 能回查真实文本 · D5 `verify` 拦住编造文本（中英各一）· D6 `sources` 用真实标题能命中 · D7 `sources` 对无关词给 hint 不假匹配（中英各一）· D8 缓存后 `verify` < 100 ms。

**十一领域实测（2026-10-16）**：

| 领域 | 语料 | 判据 |
|---|---|---|
| 政务 | 15,000 块真实语料（中国政府网等，中文） | **10/10** |
| RFC 技术标准 | 1,739 块真实语料（IETF，14 篇，**英文**） | **10/10** |
| 先进制造 | 25 块真实语料（赛题 3 语料） | **10/10** |
| 医疗 · 软件工程 · 金融 · 法律 · 制造标准 · 环保 · 教育 · 能源 | 各 4–6 篇合成语料（`scripts/gen-domains.py` 生成） | **80/80** |

合计 **110/110**。合成语料**只用来验证机制**，不是真实行业数据——真实数据需各自接入（`build_data.py` 的源格式与领域无关）。RFC 语料由 `scripts/fetch-rfc.py` 从 rfc-editor.org 抓取，用来验证**跨语言**：同一套判据在纯英文语料上同样成立。

**这个测试抓到的两个真缺陷（都是「只做一个领域」不会发现的）**：

1. **固定阈值在大语料上失效**（政务，15,000 块）：无关问句「量子纠缠退相干时间与黎曼猜想证明的联合推导xyz」**命中了 23 块**。根因是 `_best_substring` 的 `min_hits=5` 是**固定阈值**，大语料里任意 3 字组合都能撞上几块；小语料（16 块）撞不上所以没暴露。修法：阈值随语料规模走（`max(5, 块数 // 200)`，15,000 块 → 75），最短子串从 3 字提到 4 字。

2. **字符滑窗在英文语料上会切出「词的碎片」**（RFC，1,739 块）：无关英文句被滑窗切出 `lement`——它既是 `entanglement` 的子串，又是 `element` 的碎片，在 RFC 里**命中 556 块（32%）**，于是被判成有效主题词。中文没有词边界，字符滑窗成立；英文必须按词滑。修法：`_best_word_span`——ASCII 占比过半的长句改走**词序列滑窗**（先试 2–3 词组合，再退到单词），绝不切开一个词。

## 设计边界

1. **`verify_quote` 是线性扫描**（15,000 块约 10 ms）。语料扩大到百万级需要建倒排索引。
2. **只覆盖语料子集**（15,000 块，占全量 1,864,451 块的 0.8%）。子集外的引用会返回「未找到」——这是**正确行为**（我们只对已收录的部分作承诺），但要在提示词里说清楚。
3. **片段上限 600 字符**，超出截断加省略号。需要全文时用 `chunk_id` + `char_offset` 回原始语料取。
4. **未在 AgentArts 沙箱实测**——官方文档写明支持 UVX，但沙箱的网络策略、Python 版本、包体积上限均未知。
5. **英文语料的检索效果已完整评测（2026-10-17）**——`rfc-1024` 索引（RFC 1,739 块）上四组全跑了：A 组标题命中 n=14 → hit@1 **0.7857** / hit@3 **0.9286** / hit@10 **1.0** / MRR **0.869**；B 组出处可回查 **70/70**；C 组领域外 **20/20** 拒、领域内 **15/15** 答（词面落地 13/15 = **0.8667**）；D 组跨文档链 **N/A**（`not_applicable: true`）—— `level_of`（行政层级）本身是政务领域特定概念，英文语料没有行政层级，**不是机制缺陷也不是检索失败**。复跑：`ES_INDEX=rfc-1024 python3 tools/eval-retrieval.py --domain rfc`（快照 `evidence/eval-retrieval-rfc.json`）。`_best_word_span` 只保证「不切词」，不保证「切得对」。

## 端到端演示（`demo/ask.py`）

不依赖 AgentArts，在本机跑通与 `247-ict-track2-workflow.md` 同构的链路：

```bash
LLM_KEY=<你的 key> python3 demo/ask.py --query "国家层面的《优化营商环境条例》是哪一年出台的？"
LLM_KEY=<你的 key> python3 demo/ask.py --query "..." --inject-fake   # 演示核验会拦下编造引用
LLM_KEY=<你的 key> python3 demo/ask.py --query "..." --no-verify     # 对照组：跳过核验
```

链路：`[1] embedding → ES kNN` → `[2] list_sources` → `[3] 模型生成候选回答 + 拟引用原句`
→ `[4] verify_quote 逐条核验` → `[5] 只输出通过核验的引用`。

**实测（2026-10-16 · glm-5.3-flash · 温度 0）**：

| 问题 | list_sources | 拟引用 | 核验驳回 | 耗时 |
|---|---|---|---|---|
| 《优化营商环境条例》是哪一年出台的？ | 419 块 / 342 篇 | 2 | 0 | 4.5 s |
| 世界银行营商环境评价体系包含哪些指标？ | 44 块 / 38 篇 | 3 | 0 | 6.0 s |
| 安徽省在优化营商环境方面出台了哪些文件？ | 5,830 块 / 4,931 篇 | 5 | 0 | 8.4 s |
| 2024 年优化营商环境有哪些新政策？ | 6 块 / 6 篇 | 9 | 0 | 10.4 s |
| 《优化营商环境条例》对中小投资者保护是怎么规定的？ | 419 块 / 342 篇 | 0 | 0 | 3.5 s |
| **人工注入 1 条编造引用**（`--inject-fake`） | — | +1 | **1** | 5.5 s |

**这批问题里模型没有编造**（驳回 0），所以额外做了注入实验：手工塞一条语料里
不存在的引用，`verify_quote` 正确拦下。**核验环节是被证明在工作，而不是恰好没出错。**

**跑 demo 时踩到的两个坑**（都已修）：

1. **推理模型会把 token 预算烧在思考上**。`deepseek-v4.1-flash` 对一个简单问题就烧掉
   94 个 reasoning token，复杂问题直接把 4000 的 `max_tokens` 用光、`content` 返回空串。
   默认模型已换成 **`glm-5.3-flash`**（实测 `reasoning_tokens = 0` · 2.3 s）。
2. **模型会把整句问句当 `topic` 传给 `list_sources`**，而 `sources()` 是子串匹配 ⇒ 0 命中。
   已加三级降级：书名号/引号内的专名 → 按标点切分的长片段 → 滑窗（3–8 字，取命中块数
   最多且 ≥5 的子串）。**无关问句仍返回 0 并给出 `hint`**，不产生假匹配（实测
   「如何做红烧肉？」「量子纠缠的退相干时间是多少？」均 0 命中）。

## 对照实验：核验到底拦住了什么

「核验有用」不能靠「我让它逐字引用、它照做了、所以 0 驳回」来证明——那是循环论证。
**真正该问的是：用户自然提问（不会预先说「不许编」）时，模型给的依据有多少能回查？**

同一批 20 问、同一模型、同一检索，**只改提示词**，两组都开核验：

| 组 | 提示词 | 引用条数 | 逐字可回查 | 省略号写法 | 语料里查不到 |
|---|---|---|---|---|---|
| `strict` | 要求逐字引用 | 97 | **97（100%）** | 0 | **0（0%）** |
| `loose` | 只要求「给出依据」 | 61 | **11（18.0%）** | 24（39.3%） | **26（42.6%）** |

**`loose` 组才是核验的真实价值**：自然提问下，模型给的「依据」只有 18% 能直接回查原文，
**42.6% 在语料里搜不到**。（领域外 5 问两组都 0 引用——模型本来就会拒答，核验在这里没有额外贡献。）

**三类判定必须分开**（`verify_quote` 已区分）：

| 判定 | 含义 |
|---|---|
| `verbatim: true` | 逐字命中，拿这句话去原文里**搜得到** |
| `match: segments` | 内容在语料里，但模型用了「……」省略——**不是原文，要精确回查得让它给全文** |
| `verified: false` | 语料里查不到，**不能当依据用** |

**「查不到」不等于「编造」**：手工核查 26 条，多数是拼接改写（内容真但加了注释、接了另一段），
少数是真编造。但对「可回查」这个要求来说三类都不合格——**用户搜不到就是搜不到**。

### 优化记录（2026-10-16）

重跑实验前的探测发现两个真问题，已修：

| 问题 | 表现 | 修法 |
|---|---|---|
| **性能** | `verify` 40 字输入 **679 ms/次**（遍历 15,000 块、每次重算规范化） | 加 `Corpus._norm()` 惰性缓存 ⇒ **0 ms** |
| **逆序拼接** | 「市场化、法治化……国际化营商环境」在某篇里间隙 **−445 字**（段 2 在段 1 之前）却通过 | 分段匹配要求各段**按原文顺序**出现，逆序直接拒绝 |

另外 `segments` 命中现在返回 `gap_max` / `span_ratio`——**跨度作为事实返回，不替你下判断**。因为实测只有两档样本（合法省略间隙 22 字 / 拼接 357 字），拍脑袋定阈值会误伤真省略。

**仍拦不住的**：正序 + 大间隙的拼接。调用方看 `span_ratio`（0.422 = 跨度占全文 42%）自己决定要不要接受这条「引用」。这是透明化，不是解决。
