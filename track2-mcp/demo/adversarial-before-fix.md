# t2 · verify_quote 对抗测试（2000 块样本 · 2026-10-17）

样本：2000 块 / 1238 篇 / 162 万字，语料 `--limit 2000` 生成到 `/tmp/t2-adv/chunks.jsonl.gz`（未写入仓库）。

## 最该修的一条

- **症状**：`A……B` 里 `……` 落在否定词上时（`不得借乡村振兴之名**……**违法违规变相举债`），`verify_quote` 返回 `verified=True`、`gap_max=0`、`span_ratio=0.019`，即「紧凑省略、内容可核实」，而实际语义已反转。gap/span 两条防线对它完全失效——它不是「拼得太远」，是「拼得太近」。
- **最小复现命令**（实测通过，MCP stdio 层）：
  ```bash
  cd /home/endmin/dsh/research/ict-material-20261010/track2-mcp
  printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"verify_quote","arguments":{"quote":"借乡村振兴之名……违法违规变相举债"}}}' \
    | PYTHONPATH=src python3 -m ict_track2_mcp.server --data /tmp/t2-adv/chunks.jsonl.gz
  # → verified=True verbatim=False kinds=['segments'] gap_max=0 span_ratio=0.019 chunk=b7ea46e8cbad6f7a-0007
  ```
- **根因（文件:行号）**：
  - `src/ict_track2_mcp/lookup.py:205-206` 分段只按 `…+/\.{3,}/⋯+` 切分、只按长度过滤，**不看被省略的是什么**。
  - `src/ict_track2_mcp/lookup.py:211-219` 顺序检查只做 `pos[i] < pos[i+1]`，`cn.find(s)` 取首次出现 ⇒ 重叠不可检测；无 gap 上限；无否定词判定。
  - `src/ict_track2_mcp/lookup.py:220-226` `gap_max` / `span_ratio` **只计算、只 append，从不参与是否命中的判断**（死数据）。
  - `src/ict_track2_mcp/server.py:130-141` `verbatim` 只区分 `exact|normalized`，`segments` 一律进 `verified=True`，调用方拿到的就是「可核实」。
- **建议修法（纯标准库，零第三方依赖）**：
  1. `lookup.py:220` 处把被省略的原文取出来：`omitted = cn[pos[i] + len(segs[i]): pos[i + 1]]`，并对每段 gap 判三条廉价规则：① `re.search(r"[不未禁止严禁勿非]|除外|但|然而", omitted)` 且 quote 本身无否定词 ⇒ `omitted_negation=True`；② `len(omitted) > 40` ⇒ `long_omission=True`；③ 把 `omitted` 截断 40 字回传进 hit（`"omitted"` 字段），让人能看见省略了什么。
  2. `server.py:140` 收紧：`verified = bool(hits) and not any(h.get("omitted_negation") for h in hits)`，另出 `partial: bool`；`message` 改为「省略处含否定/转折词，引用语义可能与原文相反」。这样 C2/C3/C6a 全部降级，C1/C4/C5 仍按 `long_omission` 提示。
  3. `lookup.py:212` 顺序检查改用游标：`j = cn.find(s, start)`，命中后 `start = j + len(s)` ⇒ 重叠段（C5 的 `优化营商环境……营商环境` 类）可被检出。
  4. 可选：`min_len` 从 6 提到 8。依据是实测「优化营商环境」6 字命中 834/2000 块（41.7%），6 字在 2000 块语料里已无区分度；代价是会误伤短专名，需调用方接受。
