# 数字口径表（每个数从哪来、和谁不能相除）

> 答辩时被问「这个数怎么来的」的速查。**同一行的数可以比，不同行的不能比** —— 这是今天翻出来的四类「单独看都对、放一起矛盾」。

## 一、语料链（一条线，每步都在减少）

| 步骤 | 数字 | 口径 | 出处 |
|---|---|---|---|
| 原始语料 | **757,810 条 / 4.18 GB / 1,573,943,413 字符** | ModelScope `peopletech/government` 的**文档数**；4.18 GB 是压缩包，15.7 亿是正文 | `01` §4.6 |
| 清洗后 | **692,698 条** | 去掉空文档、重复、非正文后的**文档数** | `tools/corpus-clean.py` |
| 块化 | **1,864,451 块** | 每块带 `doc_id + char_offset`；一块 ≈ 800–1200 字 | `tools/chunk.py` |
| 本体抽取切片 | **60,000 块** | **全量块化的前 60,000 块**（不是按关键词选的） | `236` §8 |
| 检索入库 | **15,494 块** | 按 `--kws 营商环境 --limit 15000 --per-doc 3 --years 2006-2024 --top-sources 40 --seed 42` 选的**子集**，去重后 15,494 | `复核命令` §M |
| 英文语料 | **1,739 块** | RFC 文档，索引 `rfc-1024` | `复核命令` §R |

**不能相除的**：`60,000` 与 `15,494` 是**两个不同的选集**（一个是「前 60,000 块」，一个是「按关键词筛的」），`188,423 / 15,494` 没有意义。

## 六、如果被问「哪个数你最不确定」

按这个顺序回答（诚实度递增）：

1. **`hit@1 = 0.6`** —— 指标本身没问题，但**按文件去重后是 0.50**，我说 0.6 时指的是「top-1 里有正确文件的块」。
2. **`1,762 真文件`** —— 这是**模型判定**，零人工确认。我说「真文件」时指的是「模型判为真文件」。
3. **`15,870 条边`** —— 建立在上面那个「模型判定」之上，模型错一条，边就少一条。
4. **`D 组` 在 RFC 上是 `N/A`** —— `level_of()` 硬编码了中文层级词，英文语料全落兜底值；2026-10-17 起 `level_of` 对 `RFC \d+` 返回「未知」、评测层报 `not_applicable: true`。**这不是「检索失败」，是「指标不适用」**。

## 七、每个数能不能当场验

评委问「这个数我现在能验吗」时，按这三档回答。**`tools/verify-all.sh` 一条命令验的是第一档**。

| 档 | 含义 | 表里哪些数 |
|---|---|---|
| **✅ 当场可验** | `tools/verify-all.sh` 或 `复核命令.md` 有现成命令，包内数据齐全 | 166 文件完整性 · track2 四层 94 条 · 演示链路 4 条 · 双侧评测 hit@1 / grounding / abstain / answer（`--domain gov` 与 `ES_INDEX=rfc-1024`）· 23 项预检 · 两个索引块数（ES `_count`） |
| **⚠️ 需额外数据** | 命令在 `复核命令.md` 里，但**输入数据不随包分发**（`ict-corpus-chunks/chunks.jsonl` 等，几百 MB） | **1,864,451 块** · **188,423 条三元组** · **116,958 实体** · **14,035 节点 / 148,005 边 / 171,552 对** · **14,058→1,762 / 31,934→6,890 / 15,870 边** · **60,000 块切片** |
| **❌ 只能看记录** | 需要人工标注、外部服务或当时的环境，现在无法重跑 | **757,810 条 / 4.18 GB**（原始数据集需从 ModelScope 下）· **0.49 / 0.8 块每秒**（CPU 时代的导入实测，当时的环境）· **387 / 635 条每秒**（需 GPU + 当时的 batch）· **63 分钟**（全量判定耗时）· **hit@1 去重后 0.50**（需重跑评测并改统计口径） |

**为什么要把这个分档写出来**：第二档的数占了答辩稿里最有分量的几个（188,423、15,870），但它们**都不是评委当场能验的**——能验的是「这些数是怎么算出来的」：`复核命令.md` 的 Q1–Q7 给了完整命令与输入格式，评委可以拿自己的语料跑同一套脚本。**这是「方法可复现」，不是「结果可当场复现」**，两者要分清。

第一档的数才是真正的当场证据：171 个文件的 sha256、96 条判据、四条演示命令的 70–132 毫秒——这些**评委可以自己敲**。
