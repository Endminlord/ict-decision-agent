# 238 · LLM 判定器：规则层判不出的那部分，交给模型判

> 起因是 `237` 量出来的一个缺口：规则层的引用链**可信到 2 跳，第 3 跳开始掺短语**
> （「环境标准」「与之相伴的全球经贸规则」这类正文片段被当成了文件名）。
> 这不是再堆正则能解的——形态像文件名的短语和真文件名，靠词表分不开。
> 所以补第三层：**规则管召回、模型管判定、人工闸门管入库**。

## 1. 分工（写进材料的说法）

| 层 | 职责 | 手段 | 产物 |
|---|---|---|---|
| 规则层（`build.py`） | **召回**：宁可多抓，不漏 | 后缀 + 前缀 + 长度门槛 + 置信度分级 | 255,451 条三元组 |
| 模型层（`judge.py`） | **判定**：逐条判真伪，带理由 | 零温度批量判定 + 缓存 + 校验 | `judged*.jsonl` |
| 人工闸门（`schema.json` 的 `review_gate`） | **入库**：只放行确认过的 | 只有 high 可自动入库 | 本轮仍为 0 条 |

## 2. 实现

- **批量判定**：一批 20 条候选发给模型，要求返回 JSON 数组 `{"i","is_doc","reason"}`；零温度；带围栏剥离（模型常把 JSON 包在 ``` 里）。
- **缓存**：`judge-cache-<side>.jsonl`，键 = 候选文本 sha256 前 16 位。同一候选第二次不重复调用——判定可复现且不烧 token。
- **校验**：`validate_judgement()` 在入库前强制检查 `is_doc` 是布尔、`reason` 非空。理由不是装饰：材料里凡说「模型判为文件/非文件」，都要能同时给出判据依据。
- **自测** `--self-test` **5/5**（空理由/is_doc 非布尔被拒 · 缓存命中不重复调用 · 正负例映射 · 候选去重与过滤 · 围栏剥离与坏 JSON 抛错）。

## 3. 实测：两侧噪音都测了

用自备网关的 `deepseek-v4.1-flash`（零温度）各判 400 个候选：

| 侧 | 候选 | 判为文件 | 占比 | 判为非文件 |
|---|---|---|---|---|
| **object（被引用者）** | 400 | 35 | **8.8%** | 365 |
| **subject（引用者）** | 400 | 6 | **1.5%** | 394 |

判为文件的样例（object 侧）：`中华人民共和国民营经济促进法`、`中国共产党纪律处分条例`、`粤港澳大湾区发展规划纲要`、`全国智慧农业行动计划（2024—2028年）`、`中华人民共和国和苏里南共和国引渡条约`。

判为非文件的样例（object 侧）：`落实落细基本民生保障各项政策措施`、`细化实化优化配套措施`、`馆员的意见`、`确保城市数字化进程依法`。

判为非文件的样例（subject 侧）：`第二十二次全省民政会议召开`、`省政府党组第36次会议暨省政府第61次常务会议召开`、`以创新举措营造生育友好社会环境 完善政策体系推动人口高质量发展`。

**subject 侧噪音比 object 侧严重 6 倍**（1.5% vs 8.8%）。原因很直接：这个语料以媒体报道为主，媒体报道会**提到**法规（object 侧因此有真文件），但媒体报道自己不是文件（subject 侧几乎全是新闻/会议标题）。

## 4. 纯度对比：双侧过滤后的真实读数

在同一批（object 与 subject 各 400 个候选共同覆盖）引用边上：

| 处理 | 边 | 节点 | 闭包对 | 深度分布 |
|---|---|---|---|---|
| ① 过滤前（规则层原样） | 688 | 139 | 499 | 1 跳 499 |
| ② 只清 object 侧 | 59 | 26 | 44 | 1 跳 44 |
| ③ 只清 subject 侧 | 52 | 2 | 44 | 1 跳 44 |
| ④ 双侧都清 | **0** | 0 | 0 | — |

**④ 为 0 是这一轮最重要的读数，也是最容易误读的读数。** 它不是说「判定器把有用的都杀掉了」，而是说：在这 688 条引用边里，**两端都是文件的边，一条都没有**。规则层抽出来的绝大多数是「媒体报道 → 提到某文件」，不是「文件 → 引用文件」。

换句话说：**在这个抽样口径下**，688 条边里没有一条是文件→文件。`237` 里那 3 跳链之所以能连起来，靠的正是「媒体 → 文件 → 文件」这种混合路径，而不是纯文件到文件。

样本规模必须一起看：各 400 个候选只覆盖 688 条边（全图 148,005 条）。**这不是全量结论**。

> ⚠ **2026-10-14 全量修正（推翻本节的一条推论）**
>
> 本节原写「**政务文件之间的显式引用链，在这个语料里比想象中稀疏得多**」，**该推论不成立**。
> 全量（object 侧 31,934 条候选全部判完）下，两端都是文件的引用边有 **15,870 条**——
> 稀疏的不是边，是**链的深度**（文件→文件图 9,167 条边里多跳边仅占 1.8%）。
>
> 抽样错在**层**：那 400 个 subject 候选里只有 6 个真文件（1.5%）、400 个 object 里只有 35 个（8.8%），
> 从噪音占九成的池子里随机抽，6×35 的组合里恰好一条边都没有。
> **正确做法是先从已确认为文件的节点出发再往外走**（全量读数与复跑命令见 `239-ict-ontology-doc2doc.md`）。
> 表内「④ 双侧都清 0 条」这个**样本事实**仍然成立，被推翻的是由它推出的总体结论。

## 5. 一个漏网

`根据国际刑事司法协助法的规定` 被判为文件（理由「法律名称，可引用文件」）——它是句子片段，正确判法应是非文件。**模型判定不是零错误**，这也是为什么 `review_gate` 把入库权留给人工。

## 6. 判据自身的修正

`--self-test` 首跑 **4/5**：J1 报「空理由未被拒」。根因是我把 J1 写成了「断言理由非空」——那是**正向检查**，不是负对照，而且当时代码里根本没有校验函数（判定记录直接入库）。修法 = 真加 `validate_judgement()` 并在入库前调用，J1 改成「构造空理由 / 非法 `is_doc`，断言被拒」。

## 7. 成本与下一步

- 全量候选 82,184 个（medium/low 的 `cites` 对象）；当前速率约 400 个/6 分钟 ⇒ 单并发全量约 **20 小时**。
- 要跑全量应先并发（网关支持多路）并扩大缓存；也可以只判**高频节点**（按出度/入度 top 取），覆盖面换成本。
- 真正的价值不在「判了多少条」，而在**这层存在且可复跑**：材料里那句「半自动化本体构建」现在两头都有东西——规则召回 + 模型判定 + 人工闸门。

## 9. 诚实边界

- 判定用的是外部模型（自备网关 `deepseek-v4.1-flash`，零温度），**不是本地模型**；换模型结论可能变，缓存里记了模型名。
- 各 400 个候选是**样本**，不是全量；§4 的 0 条边是样本读数。
- 模型判定有错（§5 一例），不能当唯一依据。
- 判定结果**尚未用于改写 `236` 的三元组产物**，只是过滤视图；`review_gate` 之后仍无一条人工确认入库。
