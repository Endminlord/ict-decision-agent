# 237 · 引用链推理：本体层的「推理」半边

> 目的：`236-ict-ontology.md` 把规则抽取做通了（255,451 条三元组、出处零失败），但那些三元组是**散点**。
> 本节回答一个更硬的问题：**把这些引用边连起来，链能连多深、每一环能不能回查**。
> 工具 `ontology/reason.py`（与 `build.py`/`align.py` 同目录，共用词表与归一化）。

## 1. 机制

- **构图**：只取引用类谓词 `cites` / `implements` / `amends` / `repeals`，节点 = 归一化后的实体名，边 = `(subject → object)`。
- **有界闭包**：从每个节点出发做 BFS，深度上限 `--max-depth`（默认 4）。不用 Floyd-Warshall——14,035 节点全闭包没必要，有界 BFS 3.8 秒跑完全图。
- **路径重建**：对闭包里的每对可达节点用 BFS 重建一条最短路径，逐环取出处（`chunk_id` / `doc_id` / `title` / `date` / `evidence`）。
- **与 retrieval MCP 的分工**：多跳检索走**向量相似度**，本体推理走**显式引用边**。前者答「像不像」，后者答「谁引用了谁」。两条路互为对照，不是替代关系。

## 2. 判据

| 判据 | 含义 | 结果 |
|---|---|---|
| R1 | 起点出发的直接边必须都在闭包内 | ✅ 14,035 个起点全部通过 |
| R2 | 传递性：A→B、B→C ⇒ A→C | ✅ 抽样全部推出 |
| R3 | 无自环 | ✅ 剔除 6 条自环后为零 |
| R4 | 最长链每一环都带 `chunk_id` 与 `evidence` | ✅ Top 20 链逐环通过 |

自测 `--self-test` **5/5**（三跳传递 / 自环剔除 / 路径逐环有序 / 缺出处被 R4 抓到 / `max_depth` 生效）。

## 3. 结果：链最多连 3 跳

| 置信度门槛 | 节点 | 边 | 闭包对 | 1 跳 | 2 跳 | 3 跳 | 4 跳 |
|---|---|---|---|---|---|---|---|
| 全部（high+medium+low） | 14,035 | 148,005 | 171,552 | 148,005 | 20,671 | 2,876 | 0 |
| medium 及以上 | 13,026 | 118,452 | 136,395 | 118,452 | 15,828 | 2,115 | 0 |
| 仅 high | 6,793 | 31,210 | 32,163 | 31,210 | 905 | 48 | 0 |

两个读数值得记下来：

- **深度天花板是 3 跳**，`--max-depth` 放到 5 也没有第 4 跳。政务文件确实存在「上位法 → 实施条例 → 地方细则」的三层结构，第 4 层极少见——这与「国家 → 省 → 市」三级体系一致。
- **长链几乎全靠 medium 撑**：2 跳链从 15,828（medium+）掉到 905（high），−94%；3 跳链从 2,115 掉到 48，−98%。high 门槛只保留「强后缀 + 专有标记」的文档名，太严；**要长链就得吃 medium，而 medium 里有噪音**。

## 4. 链条质量：暴露的噪音

medium 档的出度榜首（即被引用最多的节点）：

```
中华人民共和国国务院令（出度 428）    中华人民共和国主席令（出度 427）
关于印发长沙市城市规划管理技术规定(2024年修订版)的通知（242）
中华人民共和国政府和塞尔维亚共和国政府自由贸易协定(中文本)（238）
国新办举行"推动高质量发展"系列主题新闻发布会(司法部)（232）
```

前两条是合理的（法令被大量文件援引）。但往下就出现媒体文章标题被判成 Document，而 `cites` 的**对象**里还有整句短语：

```
构建数据保护的知识产权规则(依法治国) → 主动对接国际高标准经贸规则 → 环境标准
构建数据保护的知识产权规则(依法治国) → 主动对接国际高标准经贸规则 → 与之相伴的全球经贸规则
```

`环境标准`、`与之相伴的全球经贸规则`、`规范透明的基本规则` 都不是文件，是正文里的短语。**规则层判不出「这个书名号里的是文件还是短语」**——这正是 `236` 里第 4 个 bug 的同类问题，只是换到了 `cites` 的对象侧。

⇒ 结论：**规则层的引用链可信到 2 跳，第 3 跳开始明显掺短语**。要提纯长链，需要的不是更复杂的正则，而是**判定能力**——把 medium 候选交给模型判「是不是一份可引用的文件」。

> ✅ **已完成（2026-10-14）**：判定能力已落地（`238` 的 `judge.py` + `239` 的 `prune.py`，object 侧 31,934 条候选全量判完）。
> 判定后压出的**纯文件图**是 1,661 节点 / 9,167 边 / 最大深度 **3 跳**，多跳边仅占 **1.8%**（`239` §6）——
> 本节「规则层可信到 2 跳、长链掺短语」的结论在纯文件图上**依然成立**，而且现在能说清机制：
> 真文件之间是**浅而宽**的（法规被大量引用、但被引的法规很少再往外引），
> `237` 里那 20 条 3 跳链其实是**同一条骨架 + 20 个短语尾巴**（`239` §6.1）。

## 5. 判据自身的两次修正

写这一节是因为两次都是**判据错了，不是代码错了**：

1. 首跑 R1 报「闭包漏掉 62,804 条直接边」、R2 报「传递性失败」。根因是闭包**有界**（只从起点出发），而判据按「全图闭包」的假设写。修法 = R1/R2 限定在起点可达范围内断言。这不是放松判据——原写法测的是「为什么不做全图闭包」，不是正确性。
2. `--self-test` 首跑 **0/5**：`case()` 把「函数正常返回」当成失败，方向反了。修法 = 正常返回即预期成立，抛 `AssertionError` 才算漏网。

## 7. 诚实边界

- 闭包是**有界**的（起点全图、深度 4），不是数学意义上的完全传递闭包；文档里凡说「闭包」均指此。
- 3 跳天花板是**本语料子集（60,000 块）**的读数，不是政务文件体系的普遍结论。
- 链条只反映**同一批块内**被抽出的引用边；跨文档但不在抽取范围内的引用不会出现。
- 第 3 跳开始掺短语（见 §4），**不应当直接拿去做「制度依据」的对外表述**。
- 全部置信度分档只影响是否入链，不改动 `236` 的三元组产物本身。
