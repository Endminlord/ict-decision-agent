# 239 · 双侧过滤全量：规则层判不出的那部分，模型判完之后还剩什么

> `238` 的 §4 用 400+400 个候选做样本，得出「双侧都清 = **0 条边**」，
> 并由此推论「政务文件之间的显式引用链比想象中稀疏得多」。
> 这一步把样本换成全量，结论要改：**边不稀疏，但链很浅**。
> 改在哪、为什么样本会得出 0、全量读数是什么 —— 是这份文档的全部内容。

## 1. 缺口：238 的样本抽错了层

`238` §4 的口径是「object 与 subject **各 400 个候选**共同覆盖的引用边」= 688 条。
在这 688 条里，两端都判为文件的 = 0。

问题出在**候选是怎么抽的**：

| 侧 | 抽 400 个候选 | 其中真文件 | 占比 |
|---|---|---|---|
| subject | 从全部候选里随机抽 | 6 | 1.5% |
| object | 从全部候选里随机抽 | 35 | 8.8% |

要测「文件 → 文件」的边，得先站到真文件上再往外走。
从全部候选里随机抽 400 个，抽到的大多是媒体报道标题（这个语料以新闻为主），
6 个真文件 × 35 个真文件 的组合里恰好一条边都没有 —— **0 是这么来的，不是引用链真的没有**。

> 方法论上的教训：**抽样要先分层，再抽**。在噪音占 90% 的池子里随机抽，
> 抽到的边几乎全是「媒体 → 提到文件」，这正是 `237` 里 3 跳链要掺混合路径的原因。

## 2. subject 侧全量判定（已完成）

`judged-subject-full.jsonl`，14,058 个候选（governance 语料四谓词的 subject 去重）：

| 读数 | 值 |
|---|---|
| 候选 | 14,058 |
| 判为文件 | **1,762**（12.5%） |
| 判为非文件 | 12,296 |
| 缓存命中 | 5,800（可复跑、不重复烧 token） |

比样本版的 1.5% 高，因为全量里含了「已经像文件名的那些」（规则层的强后缀命中者），
样本版抽的是均匀分布。

## 3. 剪枝口径：从真文件出发

用 §2 的 1,762 个真文件当 subject，收集它们四个引用谓词（`cites` / `implements` / `amends` / `repeals`）的 object：

| 读数 | 值 |
|---|---|
| 引用边（subject ∈ 1,762 文件） | **65,199** |
| object 去重候选 | 32,016 |
| 减去已判定的 | 82 |
| **待判定清单** `object-prune-todo.txt` | **31,934** |

这一步是**分层抽样的落点**：不再从全池抽，而是从「已确认是文件」的节点往外走一圈。

## 4. object 侧全量判定（已完成）

`judge.py --candidates-file object-prune-todo.txt --limit 0 --batch 40 --workers 8`

并发定标（实测）：

| 并发 | 待判条数 | 耗时 | 吞吐 |
|---|---|---|---|
| 1 | 40 | 141 s | 0.28 条/s |
| 8 | 120 | 61 s | **1.97 条/s** |
| 16 | 160 | 99 s | 1.62 条/s |

**16 并发比 8 并发慢** ⇒ 网关侧是瓶颈，加并发无益。选 8。

**结果**：清单 31,934 条**全部判完**（缓存 `judge-cache-object.jsonl` 32,490 条，含此前样本），
判为文件 **6,890（21.6%）**、非文件 25,044。22:21 启动 → 23:24 收尾，约 63 分钟。

object 侧判为文件的比例（21.6%）高于 subject 侧（1,762/14,058 = 12.5%）——因为清单是从真文件的引用里捞的，
天然更可能是文件名。

**字典序偏差的最终读数**（这是中间阶段最需要修正的一处）：

| 分段 | 条数 | 判为文件 | 比例 |
|---|---|---|---|
| 段 1（年份字头 2023/2024…） | 7,983 | 2,301 | **28.8%** |
| 段 2 | 7,983 | 1,535 | 19.2% |
| 段 3 | 7,983 | 1,547 | 19.4% |
| 段 4 | 7,985 | 1,507 | 18.9% |

**中间阶段观察到的「分段 8%–70% 剧烈波动」是小样本假象**——那是判定刚跑 2,520 条时的分段读数，
每段只有 504 条，噪声压过信号。全量下只有段 1 略高（年份字头的「2023年…申报书」类确实更像文件名），
其余三段稳定在 19% 上下。**结论：中间值不可外推是对的，但「强偏」是错的。**

## 5. 双侧过滤读数（全量）

`prune.py` 一次给出四阶段读数：

| 处理 | 边 | 节点 |
|---|---|---|
| ① 原样（四谓词全边） | 202,553 | 119,258 |
| ② 只清 object 侧 | 24,495 | 11,492 |
| ③ 只清 subject 侧 | 65,199 | 33,738 |
| ④ **双侧都清** | **15,870** | **8,532** |

**④ 是 15,870，不是 0。** 与中间值（3,905，object 判定仅 10.8% 时）相比翻了四倍——
object 判定从 10.8% 覆盖到全量后，两端都是文件的边持续增加。

**留存率**：subject ∈ 文件 的边共 65,199 条（③），其中两端都是文件的 15,870 条（④）
⇒ **24.3%**。中间值算出的 53.6% 偏高，因为**先判的 object 命中率更高**：
前 7,291 条留 3,905（53.6%），后 57,908 条只留 11,965（20.7%）——这与 §4 段 1 比例最高（28.8%）一致。

**所以 `238` 的两句话要分开看**：

| 238 的说法 | 判定 |
|---|---|
| 「在这 688 条边里两端都是文件的边一条都没有」 | 在它自己的口径内**成立**（样本事实） |
| 「政务文件之间的显式引用链比想象中稀疏得多」 | **不成立**（把样本事实当成了总体结论） |

实际情形：**文件 → 文件 的引用边有 15,870 条**，
稀疏的不是边，是**链的深度**（见 §6）。

## 6. 文件→文件图是「浅而宽」

对全量产物（`triples-doc2doc.jsonl`，15,870 条边）跑 `reason.py`：

| 读数 | 值 |
|---|---|
| 节点 | 1,661 |
| 边 | 9,167 |
| 闭包对 | 9,335 |
| **最大深度** | **3 跳** |
| 深度分布 | 1 跳 9,167 · 2 跳 **159** · 3 跳 **9** |
| 判据 | R1–R4 全过 |

**9,167 是 15,870 条输入边去自环 6 条、再按规范化节点名合并重复后的结果。**

对照 `237` 的混合图（媒体 + 文件，14,035 节点 / 148,005 边）：最大深度也是 **3 跳**，
但它的 2 跳 / 3 跳分别有 20,671 / 2,876 条 —— **文件→文件图的深层边占比小两个数量级**。

谓词分布（15,870 条）：`cites` 11,706 · `implements` 2,659 · `amends` 986 · `repeals` 519。

**区分出来了**：
- 文件 → 文件的引用图**浅而宽**：法规被大量引用（入度高），但被引用的法规很少再往外引 —— 链连不深。
  **不是纯星状**（有 159 条 2 跳、9 条 3 跳），但多跳边只占 **1.8%**。
- `237` 里那 3 跳链确实**靠混合路径**（媒体 → 文件 → 文件）连起来的 —— 这一半 238 说对了。
- 但连不深的**原因不是边少**，是**拓扑形状**。

> 这条区分是这一步最有价值的部分：**「稀疏」和「浅」是两个不同的量**，
> 用「边数少」解释「链短」会得出错误的机制。

### 6.1 回头查 237 的 20 条 3 跳链：它们其实是同一条骨架

拿判定结果逐节点核对 `chains-top.jsonl` 里 `hops=3` 的那 20 条，**20 条共享同一条骨架**：

```
构建数据保护的知识产权规则(依法治国)            ← 短语（正文片段）
  └─cites→ 中共中央办公厅国务院办公厅关于数字贸易改革创新发展的意见   ← 真文件 ✓
              └─cites→ 主动对接国际高标准经贸规则   ← 短语（判为非文件）
                          └─cites→ 环境标准 / 与之相伴的全球经贸规则 / 金融领域等实现规则 …
```

| 位置 | 节点性质 | 20 条里的分布 |
|---|---|---|
| 第 1 跳起点 | 短语 | 20/20 同一个起点 |
| 第 2 跳 | **真文件** | 20/20 同一个文件 |
| 第 3 跳 | 短语 | 20/20（判为非文件） |
| 第 4 跳终点 | 短语 | 19/20 是短语，只有 1 条落到真文件 |

**所以 237 里那 20 条「3 跳链」不是 20 条独立的链，是 1 条混合路径 + 20 个不同的短语尾巴。**
真节点只有中间那一个文件。

这条证据同时解释了两件事：

- `237` 说「3 跳开始掺短语」——现在有了机制：**不是第 3 跳变脏，是整条链只有 1 个真节点**，
  头尾都是正文片段。
- `239` §6 说「文件→文件图浅」——真文件之间的多跳边只占 **1.8%**（9,167 条里 168 条），连不成深链；
  而 `237` 那条 3 跳路径必须靠「短语冒充节点」撑出来（4 个节点只有 1 个是真文件）。

**顺带暴露 `reason.py` 的两个可改进点**：

1. `chains-top.jsonl` 按路径长度取 top，单一起点会把榜单淹没（这条骨架独自贡献了 20/20）。
   下一版应按**起点去重**或按结构去重后再排。
2. **节点名经过规范化**（`align.normalize`），与三元组原文有差异 ——
   `chains-top.jsonl` 里是 `构建数据保护的知识产权规则(依法治国)`（半角），
   三元组原文是 `构建数据保护的知识产权规则（依法治国）`（全角）。
   跨表按节点名匹配时必须回到原文，否则会整片匹配不上（本步第一次核对就踩了这个坑）。

判定结果回填后，这条骨架的四个节点是：

| 节点 | subject 判定 | object 判定 |
|---|---|---|
| 构建数据保护的知识产权规则（依法治国） | **非文件** | 不在 object 清单（它不是真文件的引用目标） |
| 中共中央办公厅国务院办公厅关于数字贸易改革创新发展的意见 | **文件** ✓ | 不在 object 清单 |
| 主动对接国际高标准经贸规则 | **非文件** | **非文件** |
| 环境标准（及另 19 个尾巴） | 不在候选 | **非文件**（抽核「环境标准」判非文件；「与之相伴的全球经贸规则」不在清单） |

**4 个节点里只有 1 个是真文件** —— 与 §6 的「浅而宽」互为印证。

## 7. 诚实边界

- **object 侧判定已全量完成**：31,934 条清单全部判完（缓存 32,490 条），本文档 §4/§5/§6 均为全量读数。
- **字典序偏差的最终结论**：全量下段 1 为 28.8%、其余三段稳定在 19% 上下（见 §4）——
  中间阶段观察到的「8%–70% 剧烈波动」是小样本假象（每段只有 504 条，噪声压过信号）。
  **中间值不可外推是对的，但「强偏」这个判断是错的。**
- **模型判定不是零错误**：`238` §5 记了一个漏网（`根据国际刑事司法协助法的规定` 被判为文件）。
  这类错误在 object 侧会**减少边**（把真文件判成短语），在 subject 侧会**增加边**。
- **`review_gate` 之后仍是 0 条入库**：判定结果没有改写 `236` 的三元组，也没有进知识库。
  本步产出的是**判定层读数**，不是知识库内容。
- **判定用外部网关模型**（`deepseek-v4.1-flash`，零温度），不是本地模型；
  换模型会得到不同读数，缓存键与模型名一起存（`judge-cache-*.jsonl` 的 `model` 字段）。

```bash
cd /home/endmin/dsh/research/ontology

python3 - <<'PY'
import json
docs = {json.loads(l)["candidate"] for l in open("judged-subject-full.jsonl", encoding="utf-8")
        if json.loads(l)["is_doc"]}
done = {json.loads(l)["candidate"] for l in open("judge-cache-object.jsonl", encoding="utf-8")}
LINK = {"cites", "implements", "amends", "repeals"}
objs = set()
for l in open("triples-governance.jsonl", encoding="utf-8"):
    t = json.loads(l)
    if t.get("predicate") in LINK and (t.get("subject") or "").strip() in docs:
        objs.add((t.get("object") or "").strip())
open("object-prune-todo.txt", "w", encoding="utf-8").write(
    "\n".join(sorted(objs - done)) + "\n")
PY

# 3) object 侧全量判定（后台；实测约 63 分钟，缓存逐批落盘、中断不丢）
nohup python3 judge.py --candidates-file object-prune-todo.txt --limit 0 \
        --batch 40 --workers 8 --key "$K" --out judged-object-full.jsonl \
        > /tmp/judge-obj-full.log 2>&1 &

# 4) 双侧过滤 + 四阶段读数
#    判定源用 judge-cache-object.jsonl（缓存逐批落盘，比 --out 的收尾写入更抗中断）
python3 prune.py --subject-judge judged-subject-full.jsonl \
                 --object-judge judge-cache-object.jsonl \
                 --out triples-doc2doc.jsonl --report prune-report.json

# 5) 对文件→文件子图跑引用链
python3 reason.py --src triples-doc2doc.jsonl --out reason-doc2doc.json \
        --chains chains-doc2doc.jsonl --starts 0 --max-depth 4
```
