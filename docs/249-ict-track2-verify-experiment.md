# 249 · `verify_quote` 到底有没有用？—— 对照实验

> 赛题 2 交付物。回答一个必须回答的问题：**MCP 的引用核验环节，是装饰还是真拦得住东西？**
> 实验日期 2026-10-16 · 脚本 `ict-track2-mcp/demo/experiment.py` · 原始读数 `demo/experiment.json`

## 1. 为什么重做这个实验

第一版实验的做法是：让模型答题 → 让它给引用 → 用 `verify_quote` 核验 → 报告「0 条被驳回」→ 结论「核验没问题」。

**这个实验站不住。** 因为提示词里已经写了「quote 必须逐字来自片段」——**等于把答案预设好了**：模型被要求照抄，它当然照抄，核验当然全过。**用 0 驳回去证明核验有用，是循环论证。**

真正该问的是：**用户提问时不会预先告诉模型「不许编」**，在这种自然状态下，模型给的依据有多少是语料里查得到的？**那才是核验要拦的东西。**

## 2. 实验设计

同一批问题、同一个模型（`glm-5.3-flash`）、同一套检索，**只改提示词**：

| 组 | 提示词 | 对应现实 |
|---|---|---|
| `strict` | 要求逐字引用（原 `ASK_SYS`） | 我们替模型把话说死了 |
| `loose` | 只要求「给出依据」，不说逐字（`LOOSE_SYS`） | **用户真实提问的样子** |

两组都开核验。**`loose` 组的读数才是核验的真实价值。**

20 个问题：12 个领域内（营商环境 / 放管服 / 市场主体登记 / 一网通办…）、5 个领域外（红烧肉 / 量子纠缠 / Rust 所有权 / K8s 调度 / 行星公转）、3 个边界（北京市营商环境 / 中小企业融资 / 外商准入）。

## 3. 结果

| 组 | 引用条数 | 逐字可回查 | 省略号写法 | 语料里查不到 |
|---|---|---|---|---|
| `strict` | 97 | **97（100%）** | 0 | **0（0%）** |
| `loose` | 61 | **11（18.0%）** | **24（39.3%）** | **26（42.6%）** |

**两组的差距就是核验的价值**：在用户真实提问的样子下，模型给出的「依据」里**只有 18% 能直接回查原文**。

按问题类型的 `loose` 组拆分：

| 类型 | 问题数 | 引用 | 查不到 | 查不到率 |
|---|---|---|---|---|
| 领域内 | 12 | 48 | 22 | 45.8% |
| 边界 | 2 | 13 | 4 | 30.8% |
| 领域外 | 5 | 0 | 0 | — |

**领域外 5 问两组都给出 0 条引用** —— 模型对「语料里根本没有」的问题会正确拒答，核验在这里没有额外贡献（它本来就没编）。**核验的价值集中在领域内和边界问题上。**

### 3.2 优化后重跑（2026-10-16）

修掉两个真问题（性能、逆序拼接，见 §9）后重跑同一套实验：

| 组 | 引用条数 | 逐字可回查 | 省略号写法 | 语料里查不到 |
|---|---|---|---|---|
| `strict` | 86 | **86（100%）** | 0 | **0（0%）** |
| `loose` | 60 | **15（25.0%）** | **28（46.7%）** | **17（28.3%）** |

**⚠ 这两组数字不能与 §3 直接对比**。两次跑模型相同、提示词相同、语料相同，但**模型输出本身有波动**——`strict` 组的引用总数从 97 变成 86 就是证据（那一组的要求是「逐字引用」，不可能被我们的改动影响）。所以「查不到率从 42.6% 降到 28.3%」**不能算作优化的功劳**，如实记录：这一格主要是模型波动。

改动带来的**确定性**收益在别处（§9）：核验从 679 ms/次 降到 0 ms（规范化缓存），以及**逆序拼接被拒绝**——这两条有自测守着（L19–L21），不依赖模型波动。

## 4. 三类引用必须分开看（本次实验的副产品）

最初我把「核验不通过」笼统叫「驳回」，后来手工核查发现里面混着两种完全不同的东西，于是给 `verify_quote` 加了区分：

| 判定 | 含义 | 对用户的意义 |
|---|---|---|
| `verbatim: true` | 逐字命中（`match: exact` / `normalized`） | 拿这句话去原文里搜，**能搜到** |
| `match: segments` | 内容在语料里，但模型用了「……」省略 | 内容可信，**但不是原文**，要精确回查得让它给全文 |
| `verified: false` | 语料里查不到 | **不能当依据用** |

判定逻辑（`lookup.py` 的 `verify`）：精确匹配 → 规范化匹配（去空白 + 全角转半角）→ **省略号分段**（按 `…`/`...`/`⋯` 切段，每段 ≥6 字，全部命中同一篇才算 `segments`）。

**给 `segments` 单独一档之后，读数从「71.2% 驳回」细化为「42.6% 查不到 + 39.3% 省略」** —— 这两个数字对产品的含义完全不同。

## 5. 「查不到」不等于「编造」（诚实说明）

手工核查 26 条「查不到」的引用，构成是：

- **拼接改写**（多数）：如「《优化营商环境条例》已经2019年10月8日国务院第66次常务会议通过，现予公布，自2020年1月1日起施行。总 理 李克强 2019年10月22日**（国务院令第722号）**」——内容真实，但末尾的括号注释是模型加的，整句在原文里搜不到。
- **跨块拼接**：把两段相距很远的话接成一句（原文分属不同 chunk）。
- **真的编造**（少数）：语料里完全没有对应内容。

**但这对「可回查」这个产品要求来说，三类都是不合格的**：用户拿着这句话去原文里搜，**搜不到就是搜不到**。核验拦的不是「模型是否说谎」，而是「这句话能不能被验证」——**这正是本赛题要解决的问题：不是找不到，是找到了不敢用。**

## 6. 结论

1. **提示词约束有效**：要求逐字时，模型 100% 遵守（97/97），核验 0 拦截。
2. **自然提问下核验是必需的**：只有 18% 的「依据」逐字可回查，**42.6% 查不到**。
3. **核验的语义要写清楚**：它验的是「能否逐字回查」，**不是「内容是否真实」**。前者是产品要求，后者需要人判断。
4. **省略号写法需要单独一档**：否则会把「内容真实但非原文」误算成「编造」，**虚高拦截率**（71.2% → 42.6%）。

## 7. 诚实边界

1. **样本 20 问**，一个模型（`glm-5.3-flash`），一次运行。换模型结论可能变——`deepseek-v4.1-flash` 等推理模型在本次测试中会把 token 预算烧在思考上（`reasoning_tokens` 吃满 `max_tokens`，`content` 返回空），没有参与对照。
2. **语料是 15,000 块政务子集**，不是全量 1,864,451 块；也不是企业真实沉睡资产。
3. **「查不到」的人工分类是抽样的**（26 条逐条看过），没有做完整的盲评双人标注。
4. **没有测「引用的内容是否真的支持那个结论」** —— 核验只回答「这句话在不在语料里」，不回答「这句话能不能推出这个结论」。后者需要更强的判定模型，本次未做。
5. **`segments` 分档会放宽判定**：分段后每段都命中才通过，理论上存在「两段分别来自不同语境、拼起来变味」的可能。**2026-10-16 做了对抗测试**（见 §9.1）：确认存在——间隙 357 字、跨度占全文 42%。已加顺序检查拦住逆序的，并把跨度（`gap_max` / `span_ratio`）作为事实返回；**正序 + 大间隙的拼接仍会通过**，见 §9.3。
6. **两次实验读数不可直接对比**（§3 与 §3.2）：模型输出本身有波动，`strict` 组引用总数 97 → 86 即为证据。涉及「优化带来多少提升」的说法只用在有自测守着的确定性项上（性能、逆序拦截）。
7. 实验脚本与 `ask.py` 共用检索与模型调用路径，**检索侧的缺陷会同时影响两组**（不构成对两组比较的干扰，但意味着绝对数字依赖检索质量）。

## 9. 优化记录（2026-10-16）

§7 的诚实边界里承认过一个缺口：**「拼接变味」拦不住**。这轮把它和顺带发现的性能问题一起查了、修了一部分。

### 9.1 两个真问题（探测所得）

**① 拼接变味**：`verify("优化营商环境……破坏市场秩序")` 通过了。查证命中 `11436d1d0a36615b-0001`（正文 874 字 ·《发挥综合履职优势 加强知识产权法治保障》）——段 1 在讲「促进优化营商环境、服务高水平科技自立自强」，段 2 在讲「严重破坏市场秩序、损害司法权威」，**两段语义完全无关**，间隙 357 字、跨度占全文 42%。这不是省略，是拼接。

**② 性能**：`verify` 40 字输入耗时 **679 ms/次**（6 字输入 0 ms）。根因是每次都重算 `normalize(c.text)`（遍历 15,000 块），而 `self._norm_text` 缓存字段**声明了却是死代码**。

### 9.2 改了什么

| 改动 | 效果 | 判据 |
|---|---|---|
| 新增 `Corpus._norm()`，惰性缓存规范化文本 | **679 ms → 0 ms**（缓存命中后）· 建缓存 0.70 s / 21.9 MB 内存 | L21 |
| 分段匹配要求各段**按原文顺序**出现 | 逆序（实测「市场化、法治化……国际化营商环境」间隙 −445 字）**直接拒绝** | L19 |
| `segments` 命中新增 `gap_max` / `span_ratio` | 跨度作为**事实**返回，调用方可判断是紧凑省略还是远距离拼接 | L20 |
| `sources(top=0)` 行为一致化 | 原来 `by_source` 空而 `by_year` 全量，现在 `top` 最小为 1 | — |

**为什么给跨度而不是定阈值**：实测样本只有两档——合法省略的间隙 22 字（`span_ratio` 0.042）、拼接的 357 字（`span_ratio` 0.422）。**两档之间没有更多样本，拍脑袋定阈值会误伤真省略**。所以只返回事实，不替调用方下判断。

### 9.3 仍然拦不住的

**正序 + 大间隙的拼接**仍会通过——它确实「每段都在同一篇里、顺序也对」，从纯文本匹配的角度它就是省略。现在的做法是把 `gap_max` / `span_ratio` 交出去，让工作流的调用方（或人）决定要不要接受一条跨度占全文 42% 的「引用」。**这是透明化，不是解决。**

### 9.4 自测

查询层 **18/18 → 22/22 → 27/27**（L19 逆序拒绝 · L20 跨度字段 · L21 缓存 · L22 零宽剥除 · L23 零宽不计长 · L24 4 字专名可核验 · L25 短于下限的措辞 · L26 语境不跨句 · L27 邻句否定不计入）；协议往返 **11/11 → 16/16**（M12/M13 `max_hits` 与风险事实解耦 · M14/M16 params 非对象回 -32602 · M15 畸形请求后进程存活）。三层合计 **6 + 27 + 16 = 49 条判据**（含领域无关 10 条为 59）。

### 10.5 这个测试抓到的两个真缺陷

**缺陷一：固定阈值在大语料上失效**（政务，15,000 块）

无关问句「量子纠缠退相干时间与黎曼猜想证明的联合推导xyz」**命中了 23 块**，且没有 hint。

**根因**：`_best_substring`（滑窗兜底）的 `min_hits=5` 是**固定阈值**。15,000 块的语料里，任意 3 字组合都能撞上几块；小语料（16 块）撞不上，所以三个新领域全过、只有大语料的政务暴露。

**修法**：阈值随语料规模走——`min_hits = max(5, 块数 // 200)`（15,000 块 → 75），同时把最短子串从 3 字提到 4 字，并让计数上限跟着阈值走（原来硬编码 50，低于新阈值会让函数永远返回 None）。

**缺陷二：字符滑窗在英文语料上会切出「词的碎片」**（RFC，1,739 块）

无关英文句 `quantum entanglement decoherence riemann hypothesis zyzzyva proof` **命中 556 块**。追下去发现命中的不是整句、也不是任何一个词，而是滑窗从 `entanglement` 里切出的 **`lement`**——它同时是 `element` 的碎片，而 `element` 在 RFC 里是高频词。

**根因**：字符级滑窗对中文成立（中文没有词边界，4 字窗口切出的大体是有意义的片段），对英文不成立（窗口会从词中间切开，切出的碎片碰巧命中别的高频词）。

**修法**：`_best_word_span`——先判 `topic` 的 ASCII 字母占比，过半则改走**词序列滑窗**：按非字母数字切词、丢掉长度 < 4 的词，先试 2–3 个词的组合（更专指），再退到单个词；**绝不切开一个词**。

**修复后**：RFC 9/10 → **10/10**；英文正常查询不受影响（`HTTP caching directives` → 33 块 · `TLS handshake certificate` → 254 块 · `RFC 9110` → 365 块）。

**这两条的意义**：**「只做一个领域」不会发现它们**——缺陷一要「同一套判据跑在规模差异很大的多个语料上」，缺陷二要「换一种语言」。

### 10.6 诚实边界

1. **合成语料只验证机制，不是真实行业数据**——真实数据需各自接入（`build_data.py` 的源格式与领域无关）。
2. **判据数从 8 条增至 10 条**：D5（编造文本）与 D7（无关词）各拆成中英两条。原来只用中文负例时，英文语料上是「送分题」——中文字符本来就不可能出现在英文正文里，测不出引擎行为。**旧读数的 72/72 与新读数的 110/110 不可直接对比**（判据变了）。
3. **领域无关性指的是「引擎」，不是「效果」**——换语料后检索质量取决于该语料本身的文本特征。RFC 语料上机制已验证（能加载、能回查、不假匹配、长句不被切碎），**英文的检索效果已于 2026-10-16 补测**（见 **§11**）：标题命中、出处可回查、领域外拒答三项**不劣于**中文语料；唯一变差的是领域内答出率（0.9 → 0.667），根因是**中文问句在英文语料上被词面判据全部拒答**（§11.2–11.4）——是取舍，不是可随手修的 bug。
4. **D6 用标题前 8 字做主题词**，依赖「标题本身是有效检索词」这个假设；标题短于 3 字的语料会自动跳过该判据。
5. **RFC 语料的切块参数是拍的**（按空行分段、合并到 1400 字符、丢弃 < 80 字符），没有针对英文技术文档调优；切块质量直接影响检索效果，这一层未评估。

## 11. 英文语料的检索效果（2026-10-16）

§10.6 边界第 3 条留的坑：领域无关性只验了**机制**，英文的**检索效果**没跑。本节补上——用同一套评测脚本（`tools/eval-retrieval.py`）在 RFC 英文语料上跑一遍，与政务中文语料的既有读数并排。

### 11.1 读数

| 组 | 政务 · 15,000 块中文 | RFC · 1,739 块英文 |
|---|---|---|
| A 标题命中（n / hit@1 / hit@10 / mrr） | 100 / 0.60 / 0.71 / 0.6418 | 14 / **0.7857** / **1.0** / **0.869** |
| B 出处可回查 | 500/500 = **1.0** | 70/70 = **1.0** |
| C 领域外拒答 | 20/20 = **1.0** | 20/20 = **1.0** |
| C 领域内答出 | 9/10 = 0.9 | 10/15 = **0.6667** |
| C 词面落地率 | 10/10 = 1.0 | 13/15 = **0.8667** |
| D 跨文档链 | 9/10 = 0.9 | 未跑 |

A 组样本量差异由语料规模决定（RFC 只有 14 篇文档，抽满也只有 14 个可作 query 的标题）。

**三项不劣于中文语料**：标题命中（hit@1 0.786 vs 0.60、hit@10 1.0 vs 0.71、mrr 0.869 vs 0.642）、出处可回查（1.0）、领域外拒答（1.0）。**唯一变差的是 C 组领域内答出率**（0.9 → 0.667），下一节就是这一项。

### 11.2 中文提问在英文语料上 5/5 拒答

RFC 的 C 组题库是**故意设计成中英对照**的（`tools/eval-retrieval.py:102-119`）：前 10 题英文问句、后 5 题中文问句，**同一批主题、同一个索引（`rfc-1024`）、同一个 embedding 模型**（bge-m3 1024 维），只变问句语言。

| 问句语言 | 答出 | max_score 范围 | grounded |
|---|---|---|---|
| 英文 | **10/10** | 0.7976 – 0.8721 | 1 – 5 |
| 中文 | **0/5** | 0.8182 – 0.8518 | **全部 = 0** |

5 题中文问句：HTTP 缓存 / TCP 拥塞控制 / TLS 1.3 握手 / JSON 语法 / DNS 解析。

### 11.3 根因：拒答判据是词面的，跨语言必然失效

拒答判据在 `tools/eval-retrieval.py:258`：

```python
"insufficient_evidence": max_score < 0.75 or not grounded,
```

`grounded` 来自 `keyword_grounded(query, body + title)`（`tools/cross-doc-demo.py:107`）——**用用户问句去和检索到的块正文做词面匹配**。中文问句碰上英文正文，汉字片段命中数为 0 ⇒ `grounded = 0` ⇒ 拒答。

**关键：向量召回本身是成功的。** 5 题中文问句的 `max_score` 是 0.8182–0.8518，**全部高于 0.75 阈值**，且与答对的英文问句（0.7976–0.8721）**区间重叠**。bge-m3 的跨语言召回把正确的块找出来了，是**词面判据把答案扔掉的**。

同一个根因在中文语料上还有另一种表现：政务 C 组拒掉的那 1 题「放管服改革的主要举措有哪些？」（`max_score = 0.8524`，比答对的 8 题里好几题还高）也是 `grounded = 0`——`放管服` 是 3 字缩略词，低于滑窗 4 字的最小窗口。该例已在 `245-ict-retrieval-eval.md` §4.2 记录。

### 11.4 但词面判据不能去掉

直觉修法是「跨语言时只看向量分」，数据不支持——**领域外拒答的主力恰恰是词面判据**：

| 语料 | 领域外 20 题 max_score 范围 | 超过 0.75 阈值的题数 |
|---|---|---|
| RFC 英文 | 0.6934 – **0.7600** | **1 / 20** |
| 政务中文 | 0.6739 – 0.7466 | 0 / 20 |

RFC 侧「怎样在 Excel 里做数据透视表？」拿到 **0.7600**，**越过了 0.75**——单靠向量阈值会漏拒。40 题领域外问句**全部** `grounded = 0`，是词面判据把它们拦住的。

所以这是一个**真实的取舍**，不是可随手修的 bug：

- 词面判据 = 领域外拒答的主力（去掉它，领域外漏拒）
- 词面判据 = 跨语言 / 同义改写的拦路石（保留它，中文问英文语料全拒）

**本轮没有改判据。** 理由是改动会动到全部既有读数（政务 20/20、RFC 20/20、B 组 1.0 都建立在现判据上），而这一轮的目标是**补测**不是**调参**；真要改，得连带重跑两侧全部读数，并把「领域外漏拒」的代价一起算进去。同一立场已记录在 `244-ict-finals-gap.md:92`（「未修——改判据会影响生产逻辑」）。

### 11.5 诚实边界

1. **A 组样本量不可比**（14 vs 100）——RFC 只有 14 篇文档，抽满即 14；hit@1 0.786 的置信区间比政务 0.60 宽得多。
2. **中文问句只测了 5 题**，且都是技术名词直译（HTTP / TCP / TLS / JSON / DNS 本身是拉丁字母缩写，跨语言不译）。若问句是纯中文术语（如「超文本传输协议缓存」），结果可能不同——**未测**。
3. **未测反向**（英文问句问中文语料）——政务语料上没有英文题库。
4. **D 组（跨文档链）没在英文语料上跑**。
5. **切块参数仍是拍的**（§10.6 第 5 条），英文语料没针对技术文档调优。
6. 本轮**没有修改任何判据**，249 既有结论不受影响。

### 12.3 新暴露的问题：`level_of` 是领域硬编码（D 组英文 0/15 → 已标 N/A）

RFC 侧 D 组 **0/15** 不是新缺陷，是 §10.1「耦合点扫描」**漏掉的一处**：

```python
def level_of(rec) -> str:
    """粗判层级：国家 / 地方 / 媒体。"""
    src = (rec.get("process_source") or "") + (rec.get("title") or "")
    if any(k in src for k in ("国务院", "中共中央", "全国人大", "中国政府网")):
        return "国家"
    if "省" in src or "市" in src or "自治区" in src or "法规" in src:
        return "地方"
    return "媒体"
```

「国家 / 地方 / 媒体」是**政务领域的层级概念**，判据是**中文关键词硬编码**。英文 RFC 语料上三条中文规则全部不命中 ⇒ 每一块都落进兜底值「媒体」⇒ `level_span` 恒为 0 ⇒ D 组必然 0/15。

**这不是「英文语料坏了」，是「层级这个概念本身是领域特定的」**：RFC 文档之间没有政务那种「国家级 → 省级 → 市级」的行政层级，硬套等于把一个不存在的结构当成指标。**本轮不改**——正确的修法是让层级规则**领域可配置**（从数据派生而非硬编码），那是比 §12.1 两处更大的改动，且会牵动 D 组全部历史读数。**记录在此，作为 D 组在非政务语料上不适用的依据。**

**2026-10-17 已修（不是改规则，是改语义）**：`level_of` 加一档 —— `title` 形如 `RFC \d+` 时返回 **「未知」**，`eval-retrieval.py` 的 `eval_chain()` 检测到「全部块的层级都是未知」就报 **`not_applicable: true`**、`multi_level_rate: null`。

```python
# tools/cross-doc-demo.py
if re.match(r"^RFC\s+\d+", rec.get("title") or "", re.I):
    return "未知"

# tools/eval-retrieval.py  eval_chain()
unknown_only = bool(rows) and all(r["levels"] == ["未知"] for r in rows)
return {..., "multi_level_rate": None if unknown_only else ...,
        "not_applicable": unknown_only, ...}
```

**为什么是「标 N/A」而不是「造一套 RFC 层级」**：RFC 语料里**没有**可用于分层的元数据 —— 实测 `match_phrase "Category: Standards Track"` 只命中 **13 / 1,739 块**（chunk 化时 header 丢了），`"Standards Track"` 31 块、`"Informational"` 26 块、`"Best Current Practice"` **1 块**。硬凑一套规则等于拿 0.7% 的覆盖去支撑一个指标。而 `0/15` 与 `N/A` 在答辩现场差别很大：前者读作「你们这条指标挂了」，后者才是事实 —— **这个指标对无行政层级的语料不适用**。

政务侧不受影响（实测仍 `9/10`、`not_applicable: false`），`--self-test` 8/8，双侧其余读数逐项不变。

### 12.3.1 词面判据的自证漏洞（2026-10-17 另修）

上一轮改的是「跨语言」这一侧；同一天还发现另一条更基础的缺陷：**词面落地判定用的是第 2 跳改写后的检索式**（实体名 + 原问题），与语料必然重合 ⇒ 领域外问题也能判落地。详见 `245-ict-retrieval-eval.md` §4.4。

（接 §11.5）

1. **§11.5 第 6 条「本轮没有修改任何判据」已失效** —— §12.1 改了两处；§10 / §11 的结论本身不受影响（§12.2 逐项复核过），但**任何引用旧读数的地方都应以 §12.2 为准**。
2. **D 组在 RFC 上标 N/A**（2026-10-17 起），**不说明**英文语料的跨文档链质量差 —— 该指标在 RFC 上**仍未测**（要测需先定义 RFC 领域的层级，且语料里没有分层元数据：`Category: Standards Track` 只覆盖 13/1,739 块）。

4. **引号剥离只处理了引号与括号**（`"“”‘’「」『』《》（）()【】[]`）——破折号、间隔号、竖线等其它「软分隔」**未处理**；若公文用它们包裹缩略词，同一问题会复现。**未测**。
5. **RFC 的 D 组样本量 15**（C 组题库全量），比政务的 10 略大，但两者都不是为 D 组设计的。

## 13. `verify_quote` 的对抗加固（2026-10-17）

§9 与 §12 修的是**判据**（赛题 3 的检索链），本节修的是**工具**（赛题 2 的 `verify_quote`）。两者共用一个思路：判据的每一处「计算了但没用」都是漏洞。

### 13.1 三条绕过路径（对抗测试所得）

用 20 个构造引用打 `verify_quote`，找到 **6 个实例**，归为三条独立路径：

| 路径 | 构造 | 修前判定 | 为什么能过 |
|---|---|---|---|
| 1 正序大间隙拼接 | 两段原文相距 1051 字，`span_ratio=0.967` | `verified=True` | `gap_max` / `span_ratio` **只计算、只 append，从不参与是否命中的判断** —— 死数据 |
| 2 否定词落在引用边界外 | 引用 `滥用行政权力制定含有排除、限定竞争内容的规定`（原文是「**不得**滥用…」） | `verified=True`，**无 gap 字段** | `exact` 逐字命中，任何 gap/span 阈值都管不到 |
| 3 省略号正好吃掉否定词 | `借乡村振兴之名……违法违规变相举债`（原文「**不得**借…」） | `verified=True`，`gap_max=0`、`span_ratio=0.019` | 不是「拼太远」而是「拼太近」——省略号本身就是合法操作 |

路径 2 和 3 的共同点：**判据只看「这些字在不在原文里」，不看「省略/拼接改变没改变语义」**。而「不得」这类否定词一被切掉，引用就从「禁止」变成「陈述」。

### 13.2 改了什么

四处，全在 `src/ict_track2_mcp/lookup.py`：

1. **风险扫描与展示解耦**（B1）—— 原来 `max_hits` 截断后的列表决定 `verified`，等于**展示参数可以关掉闸门**。改成「先在全部命中上扫风险，再按 `max_hits` 展示」。
2. **否定词表 + 句内语境**（路径 2）—— `_negation_marks()` 提取引用边界外一个自然句内的否定词（`不得`/`禁止`/`严禁`/`不可`/`不得以` 等），单字 `不`/`未`/`但`/`勿` 排除「不断/未来/不但」类假否定。语境**不跨句**（H2）——跨句会把相邻条款的否定词误算进来。
3. **省略号跨度阈值**（路径 3）—— `OMIT_RUN_MAX=60`（单段省略不超过 60 字）、`OMIT_TOTAL_MAX=120`（总省略不超过 120 字）；超限标 `long_omission`。**只警告不判死**，因为合法省略可以很长。
4. **短专名可核验**（H3）—— `min_len` 从 8 降到 4，但 4–5 字要求**在块内出现 ≥2 次**且**不是泛词**；`generic` / `specificity` / `block_hits` 三个字段把判断权交回调用方。另外零宽字符（U+200B–200F / U+2060 / U+FEFF）**不计入长度**（H1），否则从 PDF 复制的引用会无辜失败。

| 层 | 条数 | 内容 |
|---|---|---|
| 单元 | 6/6 | `verify()` 本体 |
| 查找 | 22/22 | `lookup_chunk` / `list_sources` / 边界 |
| 协议 | 11/11 | JSON-RPC 握手与错误码 |
| 领域 | 10/10 | 领域无关性 |
| **合计** | **49** | 修前 48，新增 L22（零宽字符） |

### 13.4 诚实边界

1. **`min_len=6` 是权衡不是真理** —— 长度是「区分度」维度，不是「真伪」维度。`放管服改革`（5 字）、`一网通办`（4 字）、`优化营商环境`（6 字）都是真术语但很短。降到 4 会让 834/2000 的 4–5 字片段被当成专名，所以改用「出现 ≥2 次 + 非泛词」当二次过滤，**仍有误报**。
2. **`破坏营商环境` 这类「短 + 落在否定性列举里」的片段，`specificity`/`generic` 抓不到** —— 它只占 3/2000（0.15%），完全不泛。现在只做到 `fragment=True` + 句级 `context_sentence` 回传，**没有自动判定**。
3. **否定词表是中文政务词表** —— 英文 `not`/`shall not`、法律英语的 `may not` 当时**未覆盖**；**2026-10-18 已补 `_NEG_EN`（24 项，L51 判据）与繁体 `_T2S_NEG`（10 项，L52），见 §13.6**。换行业仍需换词表。
4. **省略号阈值是经验值** —— 60/120 两个数来自 15,000 块语料的分位数，**换语料要重测**。
5. **本节只覆盖 `verify_quote`** —— `lookup_chunk` 与 `list_sources` 的对抗测试未做（它们不做真伪判定，风险面小但非零）。

### 13.6 第三轮：把 9 条限定语绕过修到 0
