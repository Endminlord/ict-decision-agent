## 二、Python 第三方依赖（10 个）

| 包 | 用途 | 许可证 | 是否核心 |
|---|---|---|---|
| `numpy` | 数值计算（OCR 前置） | BSD-3-Clause | 间接 |
| `Pillow` (PIL) | 图片读写（OCR 前置） | HPND | 间接 |
| `onnxruntime` | OCR 推理引擎运行时 | MIT | 间接 |
| `rapidocr_onnxruntime` | **OCR 识别**（图文通道） | Apache-2.0 | 是（图文） |
| `PyMuPDF` (fitz/pymupdf) | **PDF 文本层抽取** | AGPL-3.0 / 商业双许可 | 是（PDF） |
| `python-pptx` (pptx) | PPT 读写 | MIT | 否（仅 deck） |
| `pptx-designer` | PPT 设计库 | MIT | 否（仅 deck） |
| `tokenizers` | 分词（judge 前置） | Apache-2.0 | 间接 |
| `websocket-client` | WebSocket 客户端 | Apache-2.0 | 否（工作台） |
| `fastmcp` | MCP 框架 | Apache-2.0 | **否**（track2 手写协议，未使用） |

**许可证合规**：9 个为 MIT/Apache-2.0/BSD 宽松许可；**唯一需注意的是 `PyMuPDF` 是 AGPL-3.0** —— 若后续商业化，PDF 抽取这条需换 `pdfplumber`（MIT）或购买商业许可。本项目为参赛作品、不分发二进制，符合 AGPL 要求。

## 五、诚实边界

1. **`fastmcp` 在依赖列表里但没用到** —— `track2-mcp` 的 MCP 协议是手写的（`server.py` 的 `handle()` 纯函数 + `http_server.py` 的 Streamable HTTP），这样做的理由是**零第三方依赖可随包分发**。`fastmcp` 只出现在 `mcp/workbench-mcp-server.py`（工作台侧，不随包）。
2. **`PyMuPDF` 的 AGPL 是本清单里唯一的许可证风险点** —— 如果评委问「能不能商用」，答案是「PDF 抽取这条要换库」。
3. **PPT 生成依赖 `pptx-designer`** —— 这只影响 `deck/build_deck.py`，不影响任何判据。
