# 附录：工程方法论与工作台数据源
## ——三层治理架构的设计源头与「真实工程状态可溯源」实践

> 本文是参赛材料《01-开发设计文档》的方法论附录。它回答一个评审必问的问题：
> **这套三层治理架构是一篇为比赛写的方案，还是一个被验证过的工程体系？**
> 答案来自一个自 2026 年起持续运行的个人智能体工作台（Endmin Lord，下称 EL）：
> 本作品的三层治理架构（宪法层 / 免疫记录 / 统计门控遗忘）是该方法论在政务检索场景的
> 系统性落地，EL 则作为**工程状态数据源**接入本作品的 MCP 服务（§3）。

## 一、设计源头：从运行时治理到检索治理的同一条公理

EL 是一个 34,000+ 行、全部本地提交历史可审计的个人多智能体工作台。其内核纪律只有一条：

> **系统不可信，因为系统会变；所以判定权必须外置，变化必须留痕受审。**

本作品的三层治理架构是这条公理在「智能体检索可信」场景的投影，对应关系如下：

| 本作品（治理方案） | EL 运行时原型 | 落地于本作品的形态 |
|---|---|---|
| 宪法层（判定权外置、配置写死） | 三层执行闸门：启动开关 + 令牌 + 授权门（默认拒绝） | `governance/constitution.json` v1.0.0：C1–C7 七条规则，运行时禁改写，修订=版本递增+人工确认 |
| 免疫记录（变更可溯源、谱系可回溯） | append-only 执行日志 + 幂等双键（事件键/意图键）+ 运行注册表落盘 | `governance/immunity_log.py`：SHA-256 链式哈希账本，回改/删插必断链 |
| 统计门控遗忘（只记录不判定、遗忘同权） | 双轨制（探索/生产）+ 判定器 + 归档禁止复活清单 | `tools/gate-wilcoxon.py` + `skills/observed/` 命名空间 |
| 防自欺（判据自证作废） | 判据三件套：每条判据附「必须失败的反例」，反例不失败则判据作废 | `tools/check-consistency.py`：文档声称 vs 仓库实际逐项对账（10/10 PASS） |

这一对应关系说明：治理架构**不是为比赛新造的说辞**，而是一个已在生产中验证的工程体系的
场景化移植——移植时保留公理，替换仪器（EL 的判据吃断言与回放；本作品的门控吃评测分数）。

## 二、治理三件套的实测结果（全部可复现，命令见《复核命令.md》）

### 2.1 门控拒绝为无证据声明背书（阴性结果如实发布）

对照实验（GraphRAG 注入 on/off，25 题逐题配对，双臂同题）实跑 73 秒：

| 结果 | 数字 |
|---|---|
| X 拒答层：图谱注入前后拒答判定 | **25/25 零漂移**（"图谱永不影响拒答"的生产级再证） |
| M 多跳层：图环对判据的翻转 | 0 胜 0 回退 25 并列 → **门控正式记录 FAIL(p=1.0)** |
| 结论口径 | 图谱增强的价值=证据丰富度+零风险增强；**不虚报通过率提升** |

门控对本作品自身声明的否决（而非仅否决他人），是其有效性的最有利证据：**没有可测的端点移动，就没有能力声明。**

### 2.2 账本防篡改是机制不是承诺

免疫账本每笔记录经 SHA-256 链式哈希（prev_hash→hash）钉死：回改任意历史记录，verify 即指认断点；
治理观测台（三面板只读投影）对未通过校验的账本**拒绝渲染**。当前账本 6 笔真实事件
（宪法登记、契约登记、五技能划入 verified、门控上线、实验登记、反例测试登记），链校验通过。

### 2.3 防投毒与遗忘同权

技能生命周期：新捕获工作流一律先入 `skills/observed/`（只记录、不判定、不进主链），
晋升唯一通道=冻结集逐题配对统计检验（Wilcoxon/McNemar 自动路由，样本量下限与显著性水平写死、
脚本拒绝放宽）+ 单题回归一票否决；废止/降级走同权门控。该设计直接针对经验投毒类攻击
（投毒样本在冻结集上必然暴露回归），并规避「聚合分数门控放行永久回归」的已知失败模式。

### 2.4 功效与边界（如实声明）

n=25 时统计功效有限（对中低效应量检验力不足），阴性结果≠无差异；分数级正式对照待语料
全量导入完成后于冻结索引上复跑（当前为增量导入中的活体索引，BM25 统计随导入变动，
实验已证实跨时刻分数比较无意义、而拒答判定稳定）。全部边界写入 RIGOR_MATRIX §5 与
EXPERIMENT_RESULTS §1.3，材料中不作超出数据的声明。

## 三、EL 作为工程状态数据源：让「工作进度」变得可当场验证

### 3.1 问题

多智能体开发链的产出（计划、对账表、提交记录、评测数字）散落在文档与日志里。评审或协作者问
「这个数字现在还对吗」，智能体若凭上下文记忆作答，无法当场判断真伪——这正是「AI 说得像真的」的典型风险。

### 3.2 做法

将 EL 工作台的**真实工程状态**（文件、提交、任务、评测运行）封装为 MCP 工具
（`workbench-mcp-server.py`），并配自建 Skill `workbench-status-report` 固化流程约束：
**必须取数、必须校验、必须标注来源**。智能体回答中的每个工程数字都可追溯到
「哪个工具、哪个文件、多少字节、什么时候」。

### 3.3 该模板的复用价值

此模式（内部系统状态 → MCP 工具 → Skill 流程约束）与业务无关，替换字段即可迁移到
企业场景：把内部系统（ERP/工单/资产库）能力暴露给智能体、同时**不允许智能体自由编造**——
智能体只能报工具返回的真数，每个数字带溯源。本作品的 `governance-policy-trace` 与
`citation-verify` 两个技能是该模式在政务检索域的另外两个实例。

## 四、方法论对参赛作品的四项实际贡献（可核验）

1. **可复核性（赛题资格项）**：「全链命令化+证据为平台原始事件流」的直接源头是 EL 的
   「文档会撒谎，命令不会」纪律；本作品提供《复核命令.md》与一致性复核脚本（10/10 PASS）。
2. **反例驱动的判据体系**：本作品每条判据附失败反例的纪律（如 X 层拒答判据、表格抽取双路径
   判据）移植自 EL 判据三件套。
3. **生产工具链**：参赛仓库的全部开发、审计、派单（含两个智能体协作产出的博客提纲与图谱
   推理题库）经 EL 工作台基础设施完成，全过程提交历史可审计。
4. **架构原创性**：三层治理的公理体系与机制设计（宪法/账本/门控/观测台）为原创设计，
   34,000+ 行运行时实现与 81 条变更日志可现场展示其演化过程。
