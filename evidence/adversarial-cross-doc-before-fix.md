# cross-doc-demo.py 检索判据边界测试（新失效模式）

## 结论（3 行内：找到 8 个真 bug）
找到 8 个真 bug：3 个该拒没拒（纯符号/SQL/URL 走跨语言门放行、4 字领域泛词放行、超长无关问句 1/8 落地放行）、4 个该答没答（零宽字符、全角文号、繁体、引号内嵌致 3 字术语失效）、1 个判据失效（C2 恒真）。

## 真 bug 清单

### bug-1 无字母无汉字的输入被 `is_cross_lingual()` 判成跨语言，从而跳过词面判据
- 症状：`python3 tools/cross-doc-demo.py --query "？？？"` → 10 环、最高分 0.9083、C5 显示「跨语言分数门 ≥ 0.8」、**答出**。`2024`、`😀😀` 同路径（函数级探针 `is_cross_lingual("2024", 中文正文)` = True）。同一输入在 `rfc-1024` 上 0.7338 被拒。
- 根因：`tools/cross-doc-demo.py:197` `return (q_zh > q_lat) != (t_zh > t_lat)`。q 全为符号时 `q_zh = q_lat = 0`，左边 `0 > 0` 为 False；中文正文右边为 True；False != True ⇒ 判「跨语言」，于是 `evidence_insufficient()` 走 `:212` 的纯分数门，词面判据被完全跳过。
- 建议修法：`is_cross_lingual` 先判「query 语种未知」（`q_zh + q_lat == 0`）并直接返回 False（或让上层直接判证据不足）；更稳的做法是用**索引语种**而非逐 chunk 正文语种做决策。

### bug-2 跨语言分支只留 0.80 分数门，对无实义的拉丁串无效
- 症状：`--query "SELECT * FROM policies"` → 10 环、0.8555、答出；`--query "https://www.gov.cn/zhengce/"` → 10 环、0.8615、答出。两者正文里既无 `policies` 也无 `zhengce`。`What is GPP?` 被拒仅因 0.7713 差 0.029。
- 根因：`tools/cross-doc-demo.py:188` `CROSS_LINGUAL_MIN = 0.80` + `:212` `return max_score < CROSS_LINGUAL_MIN`。本语料 kNN 最高分分布在 0.70–0.91（15 个问法实测 0.7070–0.9083），0.80 与同语言 0.75 门几乎同一量级；kNN 永远返回 top-k，bge-m3 对任意短串都给 0.85 量级。
- 建议修法：跨语言分支不能放弃词面证据，应改为「索引语种 ≠ query 语种 ⇒ 直接证据不足」（本系统每个索引单一语种）；若确需跨语言检索，用「query 语种 == 索引语种」判定后再走 0.75 门，而非用分数门替代词面。

### bug-3 领域泛词未纳入 `_CN_GENERIC`，且 `min_frag=1` 是绝对阈值
- 症状：`--query "政策规定"` → 9 环、1/9 落地、0.8648、答出（链条全是「招商引资政策」「营商好政策」等无关块）。192 字纯技术问句（含 8 个子问题）末句挂「政策依据」→ 1/8 落地、0.8100、答出。
- 根因：`tools/cross-doc-demo.py:115-121` 的 `_CN_GENERIC` 只有疑问词与方法类词（如何/什么/测量/做法…），不含政策/规定/制度/管理/服务/办法这类政务域高频泛词；`:130` `min_frag: int = 1` 与 `:183` `return hits >= min_frag` 不随 frag 数量缩放 —— frags 越多越容易碰巧命中。
- 建议修法：泛词表补政务域高频词（政策、规定、制度、管理、服务、办法、工作、要求、落实、推进）；`min_frag` 改为按 frags 数量自适应，如 `max(1, round(len(frags) * 0.2))`，并在 `run()` 里传 `min_frag` 而非用默认值。

### bug-4 零宽字符把词切碎后，`frags` 为空且 `short` 超长，落不进任何分支
- 症状：`python3 tools/cross-doc-demo.py --query $'营商\u200b环境\u200b条例'` → 7 环、0/7 落地、0.8489、拒；而第 1 环标题就是《优化营商环境条例》。同一问题不插零宽字符则正常答出。
- 根因：`tools/cross-doc-demo.py:165` `frags = [w for w in re.findall(r"[\u4e00-\u9fff]{4,}", core)]` —— U+200B 不是汉字，把 6 字切成 2+2+2，frags 为空；`:169-170` `short = re.sub(r"[^\u4e00-\u9fff]", "", core)` 得「营商环境条例」6 字，`return 3 <= len(short) <= 4 and ...` 因 6 > 4 直接 False。
- 建议修法：`keyword_grounded` 入口先清不可见字符（`re.sub(r"[\u200b-\u200f\u2060\ufeff]", "", query)`）；`short` fallback 的上限从 4 放宽到 8，并对 `short` 做滑窗而非整串 `in`。

### bug-5 全角数字文号与半角不等价（未做 NFKC 归一）
- 症状：`--query "国发〔２０１９〕１８号"` → 10 环、0/10、0.7693、拒；`--query "国发〔2019〕18号"`（已测正例）能答。同义输入一答一拒。
- 根因：`tools/cross-doc-demo.py:144` `for m in re.finditer(r"[\u4e00-\u9fff]{2,}〔\d{4}〕\d+号|第\d+号", query)` —— Python `\d` 匹配 Unicode 全角数字，正则**能**抓到「国发〔２０１９〕１８号」；但 `:145` `if m.group(0) in text` 拿全角串去半角正文里找，必然不中。随后落到中文分支：frags 为空、`short = "国发号"`（3 字）、`"国发号" in text` 为假。
- 建议修法：`query` 与 `text` 在进入 `keyword_grounded` 前统一 `unicodedata.normalize("NFKC", s)`（一行即可让全角文号、全角字母、全角括号全部对齐）。

### bug-6 繁简未归一，繁体问句恒拒
- 症状：`--query "優化營商環境條例"` → 8 环、0/8、0.8010、拒；对应简体「优化营商环境条例」是语料里的核心文档（第 1 环命中率 100%）。
- 根因：`tools/cross-doc-demo.py:165-183` 的 4/5/6-gram 全部用同一字符集匹配，繁体字（U+4E00–9FFF 内）与简体字不相等；`:169-170` 的 fallback 又因 `len(short) == 8 > 4` 不触发。`is_cross_lingual` 也不认为繁简是跨语言（都是汉字）。
- 建议修法：内置一份 200–400 字的高频繁简映射（政务术语够用，保持零外网依赖），对 query 与 text 双向归一到简体；或退一步：frags 全部不命中时，用 2 字 bigram 覆盖率 ≥ 0.6 兜底放行。

### bug-7 `_strip_soft_punct` 删除包裹符造成粘连，3 字术语被结构词包裹后失效
- 症状：`--query "“放管服”里的“服”指什么"` → 8 环、0/8、0.8602、拒。函数级对照：`keyword_grounded("放管服", 正文)` = True、`keyword_grounded("放管服改革的主要举措有哪些", 正文)` = True、`keyword_grounded("“放管服”里的“服”指什么", 正文)` = False。
- 根因：`tools/cross-doc-demo.py:123-127` `s = s.replace(ch, "")` 是**删除**而非替换成分隔符，`放管服` + `里的` + `服指` 粘成 7 字连续串；`:174` `for n in (6, 5, 4)` 滑窗不含 3，而「放管服」只有 3 字，4-gram 只能切出「放管服里/管服里的/…」，全不命中。
- 建议修法：包裹符替换成 `\x00` 分隔符（保留边界）；滑窗补 3 字，但仅当该 3 字两侧为分隔符/非汉字（整词边界）时才计入，避免 3 字碎片造成新的误命中。

### bug-8 C2 判据恒真，`run()` 的兜底分支是死代码
- 症状：15 个问法中凡答出的（#2/#6/#7/#10/#12/#13/#14）C2 全部 ✓，包括纯符号 `？？？`（跨层级 `['地方','媒体']`、时间 2017→2024）。
- 根因：`tools/cross-doc-demo.py:282` `"C2 跨层级或跨时间": len(levels - {"媒体"}) >= 2 or (len(dates) >= 2 and dates[0] != dates[-1])` —— 只要 ≥2 环，日期几乎必然不同，`or` 后半句恒真；因此 `:298` `if len(all_hits) < 2 or not any(checks.values())` 的 `not any(...)` 永不成立，第二个拒答出口是死分支。
- 建议修法：C2 只保留层级条件（`len(levels - {"媒体"}) >= 2`），或把时间条件改成「跨 ≥1 个自然年」；同时删除 `:298` 的死分支，或改为 `all(checks.values())` 使其真正生效（当前注释已说明判定只走 `evidence_insufficient()`，展示层不应给出恒真勾）。
